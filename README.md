# quant-jp — 日本株 1年ペーパートレード検証

日本株（日足）を対象に、**架空の資金で1年間フォワードテストを行う**ための検証環境。
実弾は一切使わない。1年後の結果で、実運用に進むかどうかを判断する。

> 設計方針・運用ルール（憲法）・合格基準は OneDrive 側の
> `_Yokote/投資/自動売買/シミュレーション設計_20260814.md` を参照。
> **このリポジトリのコードより、あちらのルールが優先される。**

## セットアップ

```powershell
# 仮想環境（作成済み）
.\.venv\Scripts\Activate.ps1

# J-Quants APIキー
$env:JQUANTS_API_KEY = "取得したAPIキー"

# 疎通確認
python check_env.py       # yfinance（APIキー不要）
python fetch_jquants.py   # J-Quants（APIキー必要）
```

## 使用ライブラリ

| 用途 | ライブラリ | 選定理由 |
|---|---|---|
| データ（主） | `yfinance` | 当日終値まで取れる。バックテストもフォワードもこれが主軸 |
| データ（検算用） | `jquants-api-client` | JPX公式。**Freeは約12週間の遅延があり最新データは取れない**ため、yfinanceの値を突き合わせて検証する基準として使う |
| バックテスト | `backtesting.py` | 現在アクティブにメンテされている |
| 成績評価 | `quantstats` | tear sheet を HTML 出力。pyfolio は非推奨のため不採用 |

### yfinanceのデータで実際に見つかった破損（2026-08-15）

**バックテストを1本回すまでに、データ側の欠陥が4種類見つかった。** すべて `dataset.py` が検出する。

| # | 事象 | 実例 | 放置するとどうなるか |
|---|---|---|---|
| 1 | 末尾のバーが未確定 | `7203.T` 2026-08-14 は出来高だけあり OHLC が NaN。**前日には値が入って見えた日が翌日NaNに変わった** | 最新日のシグナルが壊れる。データ源は過去のバーを後から書き換える |
| 2 | 価格が1/10・出来高が10倍 | `1306.T` 2026-03-30〜31 の2日のみ。分割ではない（`Stock Splits=0`、分割履歴も空）。**J-Quants(JPX公式)と突合して確定** | 戦略には「-90%暴落→+948%急騰」に見える。実際に試行#4で最大DD 91.5%という物理的にあり得ない結果になった |
| 3 | **配当が分割調整されていない** | `1306.T` 2015-07-10 の分配金が 23.0円 / 株価 161.2円 = **14.3%**（2016年以降は2.7円と正常）。`1475.T` にも同様 | `auto_adjust=True` が除権日**より前の**価格を約13%押し下げる。チャートは滑らかなままで、**リターンだけが静かに水増しされる**。実測でTOPIXベンチマークが 287% → 345% に過大表示されていた |
| 4 | OHLCの微小な矛盾 | 調整計算の丸め誤差で `Close > High` が 1e-13 程度 | 素朴に検査するとエラーだらけになる。相対1e-6の許容が必要 |

**#3が最も危険。** 壊れ方が「もっともらしい」ため、結果を見ても気づけない。
J-Quants を検算用に残しておいた判断が、#2の特定で実際に効いた。

### backtesting.py の落とし穴

`stats["Buy & Hold Return [%]"]` は **指標のウォームアップ期間だけ起点が後ろにずれる**。
同じ銘柄・同じ期間でも、移動平均60日の戦略では 148.62%、単純保有では 181.72% と別の値が出る。
表示される `Start`/`End` は同じままなので気づきにくい。
→ **戦略間で比較する数値は自前で計算する**（`dataset.buy_and_hold_return`）。

### J-Quants Free の実測された制約（2026-08-14）
- データ範囲は `2024-05-22 ~ 2026-05-22` = **約12週間前で止まる**。最新データは取得不可
- レート制限が厳しい。全銘柄の並列取得は即 `429`、その後しばらく全リクエストが弾かれる
- → 1銘柄ずつ取得し、結果は `data/raw/` にキャッシュして再取得しない

**backtrader は 2018年に開発停止しているため採用しない**（日本語記事が多く候補に挙がりやすいが、バグが放置されている）。

## 鉄則

1. 合格基準は開始前に固定する。最優先は **対TOPIXバイ&ホールドで超過リターンがプラスか**
2. **戦略を変更したら1年を数え直す**（調整され続けた記録は検証価値がゼロ）
3. 記録は毎日コミットする（後から書き換えられないことが検証の生命線）
4. **`paper/journal/` を手で編集しない**
